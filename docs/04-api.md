# 04 — API design

REST + JSON over HTTPS, documented as OpenAPI 3.1, which is generated by ASP.NET Core and snapshot-tested. The TypeScript client is **generated** from that document, so any contract drift fails the build.

## Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1`. A breaking change means `/api/v2` alongside v1. Additive changes don't bump the version. |
| Format | JSON, camelCase, `null` for absent, enums as lowercase strings |
| IDs | UUIDv7 strings |
| Time | ISO 8601 UTC (`2026-10-11T21:04:00Z`); dates as `YYYY-MM-DD` |
| Errors | **RFC 9457 Problem Details** with `type`, `title`, `status`, `detail`, `traceId`, and `errors` for validation |
| Pagination | Cursor-based: `?limit=50&cursor=…` → `{ "items": [...], "nextCursor": "…" \| null }` |
| Partial update | `PATCH` with JSON Merge Patch (RFC 7396) on explicit request DTOs. Entities are never bound directly (prevents mass assignment). |
| Concurrency | `ETag` on GET; `If-Match` required on PATCH/DELETE of items → `412` on mismatch |
| Idempotency | `Idempotency-Key` header **required** on `POST …/barcodes`, `POST …/commit` and `POST …/items`. A replay returns the stored response; a different body with the same key returns `422`. |
| Rate limiting | `429` + `Retry-After`. Limits are per user and per endpoint group (see [08](08-security-and-privacy.md)). |
| Auth | Bearer token (iOS) **or** session cookie + `X-CSRF: 1` header (web). Every endpoint requires auth unless explicitly marked anonymous. |
| Not found vs. forbidden | Resources in a library you're **not a member of** return `404`, which hides that they exist. A member lacking permission gets `403`. |

## Endpoints

`{lib}` = `libraryId`. "Role" means the minimum library role needed (`viewer` < `editor` < `owner`).

### Account and session

| Method | Path | Role | Purpose |
|---|---|---|---|
| GET | `/connect/authorize`, POST `/connect/token`, POST `/connect/revoke`, GET `/connect/endsession` | — | OpenIddict OIDC endpoints (mobile) |
| GET/POST | `/account/login`, `/account/logout`, `/account/external/{provider}`, `/account/passkey/*` | — | Server-rendered sign-in pages (web + mobile auth sheet) |
| GET | `/api/v1/me` | auth | Profile + memberships |
| PATCH | `/api/v1/me` | auth | Display name, preferences |
| GET | `/api/v1/me/sessions` | auth | Signed-in devices |
| DELETE | `/api/v1/me/sessions/{id}` | auth | Sign out one device (revokes its tokens) |
| DELETE | `/api/v1/me` | auth | **Delete account.** Requires recent sign-in (≤ 10 min). Revokes Apple tokens. Purge within 30 days. |
| GET | `/api/v1/me/export` | auth | Starts an export job → a download link (CSV + JSON zip) |

### Libraries and members

| Method | Path | Role |
|---|---|---|
| GET | `/api/v1/libraries` | auth (own memberships) |
| GET / PATCH | `/api/v1/libraries/{lib}` | viewer / owner |
| GET | `/api/v1/libraries/{lib}/members` | viewer |
| POST | `/api/v1/libraries/{lib}/invites` (v1.1) | owner |
| PATCH / DELETE | `/api/v1/libraries/{lib}/members/{userId}` (v1.1) | owner |
| POST | `/api/v1/invites/{token}/accept` (v1.1) | auth |

### Items

| Method | Path | Role | Notes |
|---|---|---|---|
| GET | `/api/v1/libraries/{lib}/items` | viewer | `q`, `kind`, `format`, `platform`, `status`, `locationId`, `tag`, `sort` (`title`, `-addedAt`, `year`, `platform`), `limit`, `cursor` |
| POST | `/api/v1/libraries/{lib}/items` | editor | From a `releaseId`, or manual details |
| GET | `/api/v1/libraries/{lib}/items/{id}` | viewer | Includes work/release details + "other copies of this work" |
| PATCH | `/api/v1/libraries/{lib}/items/{id}` | editor | `If-Match` |
| DELETE | `/api/v1/libraries/{lib}/items/{id}` | editor | Soft delete |
| POST | `/api/v1/libraries/{lib}/items/{id}:restore` | editor | Undo delete |
| POST | `/api/v1/libraries/{lib}/items/{id}:rematch` | editor | Swap the release, keep copy data |
| POST | `/api/v1/libraries/{lib}/items:bulk` | editor | Bulk patch (location, status, tags) or delete; ≤ 500 ids |
| GET | `/api/v1/libraries/{lib}/ownership?code={gtin}` / `?releaseId=` / `?workId=` | viewer | Answers "do I own this", with locations (used by web search, the offline cache and future Siri/widgets; the scanner gets ownership on every candidate anyway) |
| GET | `/api/v1/libraries/{lib}/stats` | viewer | Counts by kind/format/platform/decade |

### Scanning

| Method | Path | Role | Notes |
|---|---|---|---|
| POST | `/api/v1/libraries/{lib}/scan-sessions` | viewer to scan, editor to commit | `{ defaultLocationId?, defaultStatus? }` → `201 { id }`. There are no modes. Every candidate carries ownership, so a viewer can use the scanner to check what the library has. |
| GET | `/api/v1/scan-sessions/{id}` | session's library viewer | State + all candidates (`?since=seq` for polling) |
| GET | `/api/v1/scan-sessions/{id}/events` | same | **SSE** stream: `candidate.added`, `candidate.updated`, `photo.status`, `session.status` |
| POST | `/api/v1/scan-sessions/{id}/barcodes` | viewer | `{ codes: [{ value, symbology, copies }] }`, ≤ 50 per call. Synchronous best-effort resolve (≤ 2 s), then async for slow ones. |
| POST | `/api/v1/scan-sessions/{id}/photos` | viewer | multipart: `image` (≤ 15 MB), `trigger` (`auto` \| `shutter` \| `import`), optional `textBoxes` (on-device OCR words + rects, ≤ 64 KB) → `202 { photoId }`. **The server decides** whether the picture holds one item or many. Results arrive over SSE: one candidate (plus alternatives) for a single item, many for a shelf, none (with `photo.status: "nothing_found"`) for a misfire. |
| PATCH | `/api/v1/scan-sessions/{id}/candidates/{cid}` | editor | `{ decision, releaseId?, copies? }`: accept/reject/choose an alternative |
| POST | `/api/v1/scan-sessions/{id}/candidates/{cid}:search` | editor | Re-search with user text (for not-found) |
| POST | `/api/v1/scan-sessions/{id}/commit` | editor | Creates items for accepted candidates in **one transaction** → `{ created: n, skipped: n, itemIds: [...] }` |
| DELETE | `/api/v1/scan-sessions/{id}` | editor | Abandon |

## Example: SSE event

```
event: candidate.updated
id: 9
data: {"id":"…","seq":7,"resolution":"matched","score":0.96,"release":{"title":"…","platform":"Nintendo 64"}}
```

A picture of a single item resolves to one candidate that carries what was inferred from the picture, plus its alternatives:

```
event: candidate.updated
id: 12
data: {"id":"…","seq":12,"source":"cover_ai","resolution":"matched","score":0.94,"visualScore":0.81,
       "release":{"title":"Super Mario 64","platform":"Nintendo 64","artworkUrl":"/media/covers/…"},
       "inferred":{"completeness":"cart_only","region":"ntsc_u"},
       "yourPhotoUrl":"/media/scans/…","box":{"x":0.41,"y":0.18,"w":0.07,"h":0.52},"boxSource":"ocr",
       "alternatives":[{"title":"Super Mario 64 DS","platform":"Nintendo DS","score":0.52}]}
```

The client reconnects with `Last-Event-ID` (we use `seq`), so no updates are lost. In React Native, SSE uses `react-native-sse`. If the stream drops repeatedly, the client falls back to polling `GET /scan-sessions/{id}?since=`.

## Contract workflow

1. Change an endpoint (with its test first, per [09](09-testing-and-tdd.md)).
2. A `Verify` snapshot test of `/openapi/v1.json` fails, so you review the diff and accept it.
3. CI runs `oasdiff breaking` against `main`. Breaking changes fail unless they're in a new version path.
4. `npm run api:generate` (orval) regenerates `app/src/api/`. CI fails if the generated code isn't committed.
