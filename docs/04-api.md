# 04 — API design

REST + JSON over HTTPS, documented as OpenAPI 3.1, which is generated by ASP.NET Core and snapshot-tested. The TypeScript client is **generated** from that document, so any contract drift fails the build.

## Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1`. A breaking change means `/api/v2` alongside v1. Additive changes don't bump the version. |
| Format | JSON, camelCase, `null` for absent, enums as lowercase strings |
| IDs | UUIDv7 strings |
| Time | ISO 8601 UTC (`2026-10-11T21:04:00Z`); dates as `YYYY-MM-DD` |
| Errors | **RFC 9457 Problem Details** with `type`, `title`, `status`, `detail`, `traceId`, and `errors` for validation |
| Pagination | Cursor-based: `?limit=50&cursor=…` → `{ "items": [...], "nextCursor": "…" \| null }` |
| Partial update | `PATCH` with JSON Merge Patch (RFC 7396) on explicit request DTOs. Entities are never bound directly (prevents mass assignment). |
| Concurrency | `ETag` on GET; `If-Match` required on PATCH/DELETE of items → `412` on mismatch |
| Idempotency | `Idempotency-Key` header **required** on `POST …/barcodes`, `POST …/commit` and `POST …/items`. A replay returns the stored response; a different body with the same key returns `422`. |
| Rate limiting | `429` + `Retry-After`. Limits are per user and per endpoint group (see [08](08-security-and-privacy.md)). |
| Auth | Auth0 access token as a JWT bearer (iOS) **or** session cookie + `X-CSRF: 1` header (web). Every endpoint requires auth unless explicitly marked anonymous. |
| Not found vs. forbidden | Resources in a library you're **not a member of** return `404`, which hides that they exist. A member lacking permission gets `403`. |

## Endpoints

`{lib}` = `libraryId`. "Role" means the minimum library role needed (`viewer` < `editor` < `owner`).

### Account and session

| Method | Path | Role | Purpose |
|---|---|---|---|
| GET | `/account/login` (`returnUrl`, `reauth=1`, `link=1`, `invite`, `intent`), `/signin-oidc` | — | A browser navigation to Auth0 and back. `reauth=1` and `link=1` ask Auth0 to sign in again; `link=1` adds a sign-in method. The callback sets the `__Host-cm` cookie. Not in the OpenAPI document. |
| POST | `/account/recover` | — | Check a recovery code, then carry on to `/account/login?intent=recover`. 400 wrong code, 410 expired or used, 429 too many attempts. |
| POST | `/account/logout` | cookie + `X-CSRF` | Revokes the web session, clears the cookie, returns Auth0's logout address for the app to navigate to |
| GET | `/join/{token}` | — | Web page: the invite preview. Signed out its button is **Sign in to join**; signed in it is **Join**. |
| GET | `/api/v1/me` | auth | `MeResponse`: `id`, `displayName`, `email`, memberships. The first call with a valid Auth0 token for an unknown identity creates the account (name and email from Auth0's `/userinfo`), so a new account gets 200 with no memberships. |
| PATCH | `/api/v1/me` | auth | Display name, preferences |
| GET | `/api/v1/me/sign-in-methods` | auth | The Google and Apple identities linked to you |
| DELETE | `/api/v1/me/sign-in-methods/{id}` | auth (recent sign-in) | Unlink one. 409 for the last one. |
| GET | `/api/v1/me/web-sessions` | auth | Signed-in browsers (label, created, last seen). Your own rows only; no cookie or secret |
| DELETE | `/api/v1/me/web-sessions/{id}` | auth | Sign out one browser. Its cookie stops working at once |
| DELETE | `/api/v1/me/web-sessions` | auth | Sign out every browser, including the one you are using |
| POST | `/api/v1/me/app-sign-ins` | bearer | The iPhone registers itself after sign-in (device name, install id). Creates the row, or updates it on a repeat sign-in. |
| GET | `/api/v1/me/app-sign-ins` | auth | Your iPhones (name, created, last seen) |
| DELETE | `/api/v1/me/app-sign-ins` | auth | **Sign out all iPhones:** sets `tokens_not_before` and ends your refresh tokens at Auth0. One phone can't be revoked alone (see [07](07-authentication-and-authorization.md)). |
| DELETE | `/api/v1/me` | auth (recent sign-in) | **Delete account.** Revokes all sessions, deletes the Auth0 user. Purge within 30 days. |
| GET | `/api/v1/me/export` | auth | Starts an export job → a download link (CSV + JSON zip). The zip includes your photo files as `photos/<assetId>.jpg`, listed in `photos.json` |

### Scanning

| Method | Path | Role | Notes |
|---|---|---|---|
| POST | `/api/v1/libraries/{lib}/scan-sessions` | viewer to scan, editor to commit | `{ defaultLocationId?, defaultStatus?, mediaHint?, channel? }` → `201 { id }`. There are no modes. Every candidate carries ownership, so a viewer can use the scanner to check what the library has. `mediaHint` is `books`/`games`/`movies`/`mixed` (default `mixed`); `channel` is `home`/`in_store` (default `home`). |
| GET | `/api/v1/scan-sessions/{id}` | session's library viewer | State + all candidates (`?since=seq` for polling) |
| GET | `/api/v1/scan-sessions/{id}/events` | same | **SSE** stream: `candidate.added`, `candidate.updated`, `photo.status`, `session.status` |
| POST | `/api/v1/scan-sessions/{id}/barcodes` | viewer | `{ codes: [{ value, symbology, copies }], candidateId? }`, ≤ 50 per call (exactly 1 when bound). Synchronous best-effort resolve (≤ 2 s), then async for slow ones. `candidateId` binds the read to a Review row, which upgrades in place via the T0 path. |
| POST | `/api/v1/scan-sessions/{id}/identify` | viewer | JSON `{ snapId, trigger, engine, items: [{ localId, text, title?, creator?, edition?, completeness?, kind, platform, localMatchReleaseId? }] }`, ≤ 16 KB per item. **No image is ever sent.** Immediate hits come back in the response; the rest stream over SSE. Close calls include the top candidates' `artworkUrl`s. |
| POST | `/api/v1/scan-sessions/{id}/candidates/{cid}:art` | viewer | `{ distances: [{ releaseId, distance }] }` (1 to 5, one per release, each 0 to `scoring.art.maxDistance`): feature-print distances the phone computed against candidate artwork → the server re-scores and answers with the updated candidate. Posting again replaces the earlier distances. Answers: `409` when the item is already decided (by the person, or the session is closed) or is not a close call (`scan.art_candidate_decided`, `scan.art_not_needed`); `413` when the body is over 4 KB; `415` when it is not `application/json`; `422` when a distance names a release that is not one of the candidate's own alternatives (`scan.art_release_not_an_option`) or a distance is missing, duplicated or out of range. |
| POST | `/api/v1/scan-sessions/{id}/candidates/{cid}/photo` | editor | multipart crop, used as the item's cover ("Use my photo") |
| PATCH | `/api/v1/scan-sessions/{id}/candidates/{cid}` | editor | `{ decision, releaseId?, copies? }`: accept/reject/choose an alternative |
| POST | `/api/v1/scan-sessions/{id}/candidates/{cid}:search` | editor | Re-search with user text (for not-found) |
| POST | `/api/v1/scan-sessions/{id}/commit` | editor | Creates items for accepted candidates in **one transaction** → `{ created: n, skipped: n, itemIds: [...] }` |
| POST | `/api/v1/scan-sessions/{id}/commit:undo` | editor (the session's starter) | Undo right after "Added N items": in one transaction, removes exactly the items that commit made **for good** (not in Recently deleted), forgets the barcode links and unused private releases it learned, and reopens the session with its candidates as they were. `409` once the window (2 min) has passed, if any of those items was changed since, or if the session isn't committed. `Idempotency-Key` as for commit. |
| DELETE | `/api/v1/scan-sessions/{id}` | editor | Abandon |

### Close calls on a candidate

A candidate carries `needsArt` (true while it is an open close call: Ambiguous, or Matched by a lead under `scoring.art.closeCallMargin`; never for a barcode or a shelf-segment shot) and `alternatives`, a list of `{ releaseId, title, format, platform, year, score, creators, coverUrl, alreadyOwnedCount, artworkUrl }`. `artworkUrl` is this server's own `/media/covers/{assetId}` link and is set only while `needsArt` is true; it is `null` for an alternative with no cover the caller may see. After the phone posts `:art`, `needsArt` is false and `artDistance` holds the leader's distance.

Recognition config keys that tune this (served by `GET /api/v1/recognition/config`, validated on load):

| Key | Default | Meaning |
|---|---|---|
| `fingerprints.maxDistance` | 0.35 (0.01 to 2) | On the phone: the distance at or under which two stored feature prints count as the same picture |
| `scoring.art.closeCallMargin` | 0.15 (0 to 1) | A Matched item whose lead over the runner-up is under this is a close call (an Ambiguous one always is) |
| `scoring.art.distanceScale` | 1.0 (0.001 to 1000) | Factor applied to every reported distance before it becomes a similarity (`1 - d^2 / 2`) |
| `scoring.art.maxDistance` | 100 (0.001 to 100000) | The largest distance `:art` accepts, in the phone's units; a bigger one is a `422` |

### Admin (developer-tools role; separate route group and policy)

`/api/admin/*` needs the developer-tools role (the platform `admin` role). Nothing in the app grants it; the person at the host does, with `--dev-tools grant <email>` ([07](07-authentication-and-authorization.md)). It is not a library role and opens no library. It is for the iPhone scanner evals (`/api/admin/evals`) and the job list.

**Removed by [15](15-onboarding.md):** `GET` and `POST /setup`, `GET /account/not-linked`, the 403 `account.not_linked` (the first call creates the account), and the `setup` and `join` intents on `/account/login`.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/admin/ai-usage` | Spend by day and user |
| POST | `/api/admin/catalog/releases/{id}:verify` | Promote a user-created release to global |
| GET | `/api/admin/jobs` | Failed and pending jobs |

## Example: SSE event

```
event: candidate.updated
id: 9
data: {"id":"…","seq":7,"resolution":"matched","score":0.96,"release":{"title":"…","platform":"Nintendo 64"}}
```

A picture of a single item resolves to one candidate that carries what was inferred from the picture, plus its alternatives:

```
event: candidate.updated
id: 12
data: {"id":"…","seq":12,"source":"picture_apple_model","resolution":"matched","score":0.94,"artDistance":0.21,
       "release":{"title":"Super Mario 64","platform":"Nintendo 64","artworkUrl":"/media/covers/…"},
       "inferred":{"completeness":"cart_only","region":"ntsc_u"},
       "localId":"snap7-item3","box":{"x":0.41,"y":0.18,"w":0.07,"h":0.52},"boxSource":"ocr",
       "alternatives":[{"title":"Super Mario 64 DS","platform":"Nintendo DS","score":0.52}]}
```

The client reconnects with `Last-Event-ID` (we use `seq`), so no updates are lost. In React Native, SSE uses `react-native-sse`. If the stream drops repeatedly, the client falls back to polling `GET /scan-sessions/{id}?since=`.

## Contract workflow

1. Change an endpoint (with its test first, per [09](09-testing-and-tdd.md)).
2. A `Verify` snapshot test of `/openapi/v1.json` fails, so you review the diff and accept it.
3. CI runs `oasdiff breaking` against `main`. Breaking changes fail unless they're in a new version path.
4. `npm run api:generate` (orval) regenerates `app/src/api/`. CI fails if the generated code isn't committed.
