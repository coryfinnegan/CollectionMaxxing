# npm advisories of HIGH or CRITICAL severity that the dependency audit accepts, each with the reason (Run-DependencyAudit.ps1).
# One per line: <GHSA id> <package>: <reason>. Review when Expo / React Native is upgraded: an upgrade is the fix for all of them.
GHSA-vfj7-8cjw-p6xm braces: build and test tooling only (micromatch, used by Metro and Jest to match file globs on the developer's PC and in CI). Not in the app bundle, and the input is our own file names, not attacker input. Denial of service only. Fixed by the next Expo SDK upgrade.
GHSA-mrhx-c7xc-m3w5 zod: zod 3.x inside developer tooling only (the Expo CLI, the React hooks ESLint plugin, orval's code generator). Never in the app bundle or the server. The memory exhaustion needs a very large array handed to a zod array schema, and these tools only read our own config and OpenAPI files, not attacker input. 3.x gets no patch (fixed from 4.6.6, which those tools cannot use yet). Review when Expo, orval or eslint-plugin-react-hooks move to zod 4.
GHSA-vcc3-ghjq-m6fr decode-uri-component: inside query-string 7, which expo-router uses to parse the app's own URLs and deep links. The fix (0.5.1) is ESM-only and query-string 7 loads it with require(), so an npm override would break URL parsing; the real fix is the expo-router upgrade of the next Expo SDK. The worst case is a slow decode of a crafted link the person opens on their own phone or browser tab (denial of service to themselves only); the server never runs it. Review on the Expo SDK upgrade.
