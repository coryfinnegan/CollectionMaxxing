## Verify, merge, deliver

1. Push first (the branch is already merged with `origin/main` and gated, see "Do the work"), so CI starts. Then, while CI runs, start a separate verifier subagent (the Agent tool with `model: "opus"`, whatever model you run on; it did not write the change, fresh context). Tell it to review the PR's diff against the issue and `CLAUDE.md`'s definition of done and try to break it, and to answer PASS or one list of every finding, nits included, so one fix round covers them all. You never verify your own change. Fix all of its findings in one push (merge `origin/main` and run the gate first, as before), then verify the new head the same way; at most 2 fix rounds.
2. Squash-merge only when all three are true: CI is green on the current head of the branch, the verifier said PASS for that head, and `git fetch origin` then `git rev-list --count HEAD..origin/main` prints 0. If main moved (the count is not 0), `git merge origin/main`, run the gate, push, wait for CI again, then fetch and count again: main must never move under a PR between its last green CI and its merge. The verifier's PASS carries over a merge of main that needed no conflict fixes and no change of yours: do not start a new verifier for it, and it is not a fix round. A merge with conflict fixes, or any other code change, needs the verifier again, and that counts as a round. As soon as the count is 0 for the head that CI and the verifier passed, merge that head: `gh pr merge <number> --squash --match-head-commit <sha>`, with `<sha>` from `git rev-parse HEAD`. That is the owner's standing rule; you do not ask. Do not `git checkout main` here (main is checked out in another worktree). If `gh` complains about a local branch step after the merge, check `gh pr view <number> --json state` before you conclude anything: the merge may have happened.
3. Follow it to delivery. A change under `app/` is delivered when the "iOS build (TestFlight)" run for the merge commit succeeds. A server change (`src/**`, `deploy/**`, `contracts/**`) is delivered when the "Release images" run for the merge commit succeeds and `curl -s http://127.0.0.1:5480/health/version` reports the merge commit or a descendant. Give each about 30 minutes. Use `gh run list` and `gh run watch` in the foreground, and run the watch again when it times out (a build can outlast one 30-minute call).
4. When delivered, remove `agent-review` (`gh issue edit {issue} --remove-label agent-review`) and comment one summary on the issue: what shipped, the PR link and the delivery evidence. The PR's `Closes #{issue}` closes the issue.
